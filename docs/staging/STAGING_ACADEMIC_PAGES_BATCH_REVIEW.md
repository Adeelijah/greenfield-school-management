# Academic account pages — coordinated first batch

This batch connects admin Students (`/staging/students`), teacher My Classes (`/staging/classes`) and admin/teacher Report Cards (`/staging/reports`) to the previously verified fictional staging class indexes. The dashboard, mobile and desktop sidebar links now navigate real routes. Each route verifies sign-in and the staff lookup before academic data access; admin-only directory and teacher-only class routes reject other roles. Bursar is denied all three academic pages. Unknown or unavailable selected class scopes do not fall back to another class. Module reads and action/result links retain their own complete current authority checks.

Students provides a scoped active-enrollment directory, search by name/reference, class and report-status filters, expandable student/enrollment references and correction notes, report workflow links and links to approved/published results. My Classes shows available assigned test class cards with pupil/roster/report counts and source revision, plus links to class-filtered reports and the existing class workflow. Report Cards gives the status/task directory and the same workflow/result entry points. All show desktop tables or mobile record cards using the approved styles and shared GreenfieldDropdown. Empty filters have reset controls; unavailable reads show a retry state without fabricated zeroes or samples.

The server projection now retains class keys, enrollment/report IDs, exact report version, stage and correction reason. The route role is derived server-side, not from the URL or client state. Report directory links are not authorization: existing server workflow commands and result readers independently recheck membership, assignment, school scope, report versions and immutable content. No writes were added to these directories. The established workflow remains the action entry and its existing read-only/write opt-in still applies. Contact/guardian details, admissions, registration/editing, attendance, assessments and finance are not connected by this batch. Counts cover the two available fixture classes, not the entire school or full assignment directory.

The existing shared shell is reused rather than replacing the working report implementation. Workflow and result pages now provide navigation back to the staff/report workspace. The skeleton supports directory and class-card variants at the existing responsive breakpoints. The separate sample design preview remains separate from verified account pages.
