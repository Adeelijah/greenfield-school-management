# Academic operations read/draft milestone

Attendance (`/staging/attendance`) now uses verified active enrollment data and supports date selection, per-pupil present/absent/late/excused draft marks, an explicit mark-all-present draft action and completeness/date/status validation. Nothing is automatically marked, saved or inferred as attendance history.

Assessments (`/staging/assessments`) loads a selected class through the existing complete relational reader within the exact-role/complete-authority boundary. Teacher class AND every subject permission are rechecked. Full source materialization validates source/configuration/score bindings; missing/incomplete sources fail closed rather than emit guessed values. The client receives only selected-class pupil labels, pinned component/grading configuration and existing score/observation values. The directory/enrollment references must match. Numeric bounds/four-decimal constraints and configured descriptive levels can be checked against a local draft. Configuration components, weights and grade bands are viewable. This is not proof of authenticated teacher review or admin finalization.

Both pages retain the responsive shared shell, dropdowns, role-protected direct routes, class navigation and loading status. Numeric/observational values remain distinct. Drafts exist only in browser memory and are cleared on navigation/reload. Save, review and finalize are disabled with a visible explanation. No localStorage or server memory store substitutes for database persistence.
